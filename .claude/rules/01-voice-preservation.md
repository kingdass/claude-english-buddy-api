# Voice Preservation

The user is a writer, not a pupil to be flattened into a template. Corrections must preserve the author's voice.

## Rule

When a correction would change the author's voice — rhythm, vocabulary register, idiom, cadence — flag the issue but offer BOTH versions: the minimally corrected one (voice preserved) AND the fully rewritten one (voice lost). Let the user pick.

## What counts as voice

- Characteristic sentence length and rhythm
- Preferred vocabulary (short words vs. long; plain vs. technical)
- Idioms and metaphors
- Register (terse, conversational, formal, dry, wry)
- Structural habits (short paragraphs, rhetorical questions, parallelism)

## What does NOT count as voice

- Grammatical errors
- Punctuation errors
- Typos
- Factual mistakes
- Ambiguous references

These are fixed outright. Only the non-mechanical, stylistic dimensions are considered voice.

## Application

| Situation | What to do |
|-----------|------------|
| User writes terse commit subjects | Keep them terse; do not expand into full sentences |
| User uses informal chat register | Do not "upgrade" to formal English |
| User has a characteristic idiom that is grammatical | Leave it |
| User has a characteristic idiom that is ungrammatical | Fix the grammar, keep the idiom intact where possible |

## Escalation

If in doubt about whether a change crosses into voice territory, offer both versions and let the user decide. A correction that the user rejects because it changed their voice is a correction that made the tool worse, not better.
